# Как публиковать пакет

Пакет — `@cdd-team/openapi` в npm. В tarball попадает только `dist/`, `package.json` и `README.md`
(поле `files`). `dist/` в git не хранится и собирается при публикации.

Публикация автоматическая и общая для всех пакетов монорепозитория `frontend-packages`: вручную
пакет не публикуют. Версии, `CHANGELOG.md` и теги ведёт release-please, в npm пакет уходит из
GitHub Actions по OIDC (Trusted Publishing), постоянный npm-токен не нужен. Как это устроено, как
выпустить первую версию и что делать при частичном сбое — в [README репозитория](../../../README.md)
и [runbook выпуска](../../../docs/release-runbook.md).

## Что нужно от изменения

- Рабочее дерево чистое, CI зелёный: формат, линт, типы, тесты, сборка и проверка архивов.
- Если менялся контракт — `spec/openapi.json` и `src/api/schema.ts` обновлены
  ([как обновлять сгенерированный код](./updating-schema.md)).
- Сообщение коммита в PR отражает тип изменения: `fix:` — исправление, `feat:` — новая возможность,
  `feat!:` — несовместимое изменение. Только они дают новый релиз.

Пока версия `0.x`, несовместимые изменения выпускаются как minor: caret-диапазон `^0.2.0` у
потребителей не подтягивает `0.3.0` сам.

Что считать несовместимым изменением: смену формы сгенерированного `schema.ts`, сигнатуры `createClient`
или методов клиента, формата результата `{ data, error, response }`, аргументов CLI.

## Проверка после публикации

```sh
npm view @cdd-team/openapi version
```

И в чистом каталоге:

```sh
bun add @cdd-team/openapi
bunx openapi-cdd ./openapi.json -o ./schema.ts
```
